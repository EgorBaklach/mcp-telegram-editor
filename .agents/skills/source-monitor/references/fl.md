# 📡 FL.ru — дайджест новых заказов

Мониторинг и оценка новых заказов на бирже FL.ru по профилю разработчика (MCP-сервер `mcp-telegram-editor`). Скилл `telegram_editor_strategy` и инструмент `notify` для этого источника **не используются** — вёрстка карточки по шаблону `storage/app/templates/fl.plate.php` и отправка в Telegram выполняются автоматически внутри инструмента `notify_order`.

1. **Обнаружение:** инструмент `check_new_orders`.
   Поля каждого элемента в `new_orders`: `project_id`, `title`, `link`, `budget`, `description`.
2. **Анализ и фильтрация:** активируй скилл `developer-profile` и оцени процент совпадения каждого заказа (`0..100`) с компетенциями, стеком и проектами из профиля:
   * **Совпадение `< 50`:** пропусти шаги 3–4 и сразу пометь заказ через `mark_order` с `published: false` (шаг 5).
   * **Совпадение `>= 50`:** переходи к подготовке параметров (шаг 3).
3. **Подготовка параметров для шаблона (при `match >= 50`):**
   * `rate`: строка оценки рентабельности из расчёта `1 500 ₽/ч` (🟢 *Выгодно* / 🟡 *Обсуждаемо* / 🔴 *Ниже ставки* с оценкой трудозатрат в часах).
   * `summary`: краткое пояснение (1–2 предложения, чем именно заказ пересекается со стеком, без HTML-тегов).
   * `proposal` *(только при `match >= 75`, при `50..74` оставь пустым `""`)*: чистый текст сопроводительного предложения без HTML-тегов от первого лица на базе релевантных кейсов из `developer-profile`, примерной оценки сроков/стоимости из расчёта `1 500 ₽/ч` и контактов из `.agents/skills/developer-profile/.env`.
4. **Доставка:** вызови инструмент `notify_order` с объектом `payload` (`match`, `title`, `link`, `rate`, `summary`, `budget`, `proposal`).
5. **Фиксация:** вызови инструмент `mark_order` с `projectId` заказа:
   * `published: true` — сразу после успешной отправки через `notify_order`;
   * `published: false` — для отфильтрованных заказов (`< 50`).
