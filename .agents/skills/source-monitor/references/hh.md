# 📡 HH.ru — дайджест новых вакансий

Мониторинг и оценка новых вакансий на HeadHunter (`hh.ru`) по профилю разработчика (MCP-сервер `mcp-telegram-editor`). Скилл `telegram_editor_strategy` и инструмент `notify` для этого источника **не используются** — вёрстка карточки по шаблону `storage/app/templates/hh.plate.php` и отправка в Telegram выполняются автоматически внутри инструмента `notify_vacancy`.

1. **Обнаружение:** инструмент `check_new_vacancies`.
   Поля каждого элемента в `new_vacancies`: `vacancy_id`, `title`, `company`, `address`, `schedule`, `link`, `salary`, `description`.
2. **Анализ и фильтрация:** активируй скилл `developer-profile` и оцени процент совпадения каждой вакансии (`0..100`) с компетенциями, стеком и опытом из профиля (с учётом локации `address` и формата работы `schedule`):
   * **Совпадение `< 50`:** пропусти шаги 3–4 и сразу пометь вакансию через `mark_vacancy` с `published: false` (шаг 5).
   * **Совпадение `>= 50`:** переходи к подготовке параметров (шаг 3).
3. **Подготовка параметров для шаблона (при `match >= 50`):**
   * `rate`: строка оценки оффера относительно ориентира `от 150 000 ₽ / 1 500 ₽/ч` (🟢 *Выгодно* / 🟡 *Обсуждаемо* / 🔴 *Ниже ожиданий*).
   * `summary`: краткое пояснение (1–2 предложения, чем именно вакансия пересекается со стеком, без HTML-тегов).
   * `proposal` *(только при `match >= 75`, при `50..74` оставь пустым `""`)*: чистый текст сопроводительного письма без HTML-тегов от первого лица на базе релевантных кейсов из `developer-profile` и контактов из `.agents/skills/developer-profile/.env`.
4. **Доставка:** вызови инструмент `notify_vacancy` с объектом `payload` (`match`, `title`, `link`, `rate`, `summary`, `company`, `address`, `schedule`, `salary`, `proposal`).
5. **Фиксация:** вызови инструмент `mark_vacancy` с `vacancyId` вакансии:
   * `published: true` — сразу после успешной отправки через `notify_vacancy`;
   * `published: false` — для отфильтрованных вакансий (`< 50`).
